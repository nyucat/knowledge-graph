# knowledge_graph

本项目是一个面向“图灵相关知识”的专题知识图谱构建程序。程序围绕一篇或多篇图灵主题文本，完成以下五个核心任务：

1. 实体抽取
2. 实体消歧
3. 关系抽取
4. 输出知识三元组
5. 输出 Neo4j Cypher 脚本

它的实现不是单一模型端到端完成，而是采用“专题词典 + 弱监督训练 + 序列标注 + 规则约束 + 结构化导出”的组合方案。这种设计非常适合课程设计和答辩场景，因为每一步都有清晰的方法来源、代码落点和可解释性。

## 1. 项目目标与整体流程

项目输入主要是 `datafile/test.txt` 中的图灵人物介绍文本，最终生成：

- `outputs/turing_entities.json`：初步实体抽取结果
- `outputs/turing_entities_disambiguated.json`：消歧后的规范化实体
- `outputs/turing_relations_only.json`：关系触发词和关系类型统计
- `outputs/turing_kg_triples.json`：知识三元组
- `outputs/CY.txt`：可直接导入 Neo4j 的 Cypher 脚本

完整流程如下：

1. 读取图灵文本
2. 基于图灵专题词典进行高召回实体发现
3. 用 BERT-BiLSTM-CRF 进行弱监督实体识别训练与辅助抽取
4. 用别名映射表将同一实体的不同写法归并，完成实体消歧
5. 基于触发词规则、实体类型约束和正则规则抽取关系
6. 形成 `(head, relation, tail)` 三元组
7. 根据实体类型推断节点标签，生成 Cypher 建图语句

从实现上看，本项目实际上有两层架构：

- 通用层：`src/run_pipeline.py` 及配套的 CRF / BERT / 细粒度类型 / 消歧模块
- 图灵专题层：`train_and_extract_turing.py`、`disambiguate_turing_entities.py`、`lstm_crf_relation_extract_turing.py`、`generate_neo4j_cypher.py`

答辩时可以强调：本项目不是简单调用现成工具，而是把通用 NLP 管线针对图灵专题做了领域化改造。

## 2. 实体抽取方法

### 2.1 方法概述

图灵专题实体抽取采用“词典优先，模型辅助”的方案。

核心思想：

- 先用 `data/turing_lexicon.json` 中的专题词典做高召回匹配
- 再利用弱监督样本训练 `BERT-BiLSTM-CRF`
- 训练后的模型可以学习上下文中的实体边界和类别模式
- 但最终图灵专题的输出以词典匹配结果为主，保证“目标实体不漏掉、名称尽量标准化”

这是一种非常符合专题知识图谱构建的策略。因为图灵知识的目标实体集合相对稳定，词典可解释性强，模型主要负责补充学习边界规律，而不是完全依赖统计学习自由发挥。

### 2.2 词典抽取

代码位置：`src/train_and_extract_turing.py`

关键函数：

- `load_lexicon()`
- `extract_by_lexicon()`
- `_find_term_spans()`
- `merge_spans()`

实现机制：

1. 从 `data/turing_lexicon.json` 读取图灵领域实体词典
2. 将实体按类别分成 `person`、`location`、`organization`、`work`、`tech_theory`、`event_law`、`honor_identity`、`other`、`time_value`
3. 对每个词条在全文中做字符串匹配
4. 英文实体采用大小写不敏感匹配，中文采用精确匹配
5. 为避免短词覆盖长词，先按词长倒序匹配
6. 对重叠候选做去重，优先保留更长的跨度

这一部分本质上是“领域词典驱动的精确实体识别”。它在图灵专题里非常有效，因为图灵、图灵机、图灵测试、ACE、Enigma、Julius Mathison Turing 这类实体非常适合预先建表。

### 2.3 弱监督序列标注

代码位置：

- `src/train_and_extract_turing.py`
- `src/bert_bilstm_crf_ner.py`

关键函数：

- `split_sentences_with_offsets()`
- `weak_label_sentence()`
- `build_weak_samples()`
- `train_model()`

实现机制：

1. 先把图灵原文切分为句子
2. 用词典命中的实体在句子中自动标 BIO 标签
3. 形成弱监督训练样本
4. 将这些弱监督样本与 `data/sample_ner_train.jsonl` 中的基础训练样本拼接
5. 训练 `BERT-BiLSTM-CRF` 模型

这里体现了一个很重要的工程思想：项目并没有完全依赖人工标注图灵数据，而是通过专题词典自动制造部分训练信号。这样做降低了人工标注成本，同时让模型学到图灵语料中的上下文模式。

### 2.4 BERT-BiLSTM-CRF 的模型结构

代码位置：`src/bert_bilstm_crf_ner.py`

模型类：

- `BertBiLSTMCRFModel`
- `BertBiLSTMCRFEntityRecognizer`

结构如下：

1. `BERT` 负责把字符序列编码为上下文向量
2. `BiLSTM` 进一步学习前后文顺序信息
3. `Linear` 层输出每个位置的标签得分
4. `CRF` 对整个标签序列联合解码，保证 BIO 序列合法

其中：

- `CharTokenClassificationDataset` 把“按字标注”的样本对齐到 BERT tokenizer 的 token 序列
- `_to_i_tag()` 解决一个字被拆成多个 token 时的 BIO 标签延续问题
- `predict_labels()` 采用分块推理，避免长文本超过 BERT 最大长度

从答辩角度可以这样概括：

“BERT 解决语义表示，BiLSTM 解决顺序建模，CRF 解决标签之间的结构约束，因此比单独的 BERT 分类更适合命名实体识别任务。”

### 2.5 CRF 备选实体识别器

代码位置：`src/crf_ner.py`

虽然图灵专题主流程默认用的是 BERT-BiLSTM-CRF，但项目还实现了纯 CRF 版识别器，说明作者考虑了可替换性和实验对比。

方法特点：

- 以字为单位构造特征
- 使用前后字、bigram、字形属性、数字/字母/中文等特征
- 用 `sklearn_crfsuite.CRF` 做 BIO 序列标注

关键函数：

- `sentence_to_features()`
- `convert_bio_to_entities()`
- `merge_adjacent_entities()`
- `repair_numeric_boundaries()`
- `repair_common_prefix_boundaries()`

这部分代码说明项目不仅依赖深度学习，也保留了传统机器学习的可解释方案。

### 2.6 图灵专题最终为何“词典优先”

`train_and_extract_turing.py` 中的 `merge_spans()` 明确写了：

- 模型结果参与训练和学习
- 但图灵专题最终输出以词典匹配为主

原因是：

1. 该项目是专题知识图谱，不是开放域 NER
2. 目标实体集合相对封闭
3. 词典结果更稳定、可控、可解释
4. 答辩时更容易说明“不漏掉图灵知识点”

因此，实体抽取的真正方法总结为：

“词典高召回匹配 + 弱监督 BERT-BiLSTM-CRF 训练 + 词典优先输出”

## 3. 实体消歧方法

### 3.1 方法概述

图灵专题实体消歧采用“别名表映射 + 最长匹配 + 规范名归并”的规则化方案；通用管线中还额外实现了两种学习型消歧器。

这也是本项目非常适合答辩的地方：

- 图灵专题最终使用规则消歧，稳定、透明
- 通用框架保留了 CRF 消歧和 BERT-BiLSTM-CRF 消歧，体现算法深度

### 3.2 图灵专题消歧：别名映射表

代码位置：

- `src/disambiguate_turing_entities.py`
- 数据文件：`data/turing_disambiguation.json`

关键函数：

- `find_mentions()`
- `build_output()`

实现机制：

1. `turing_disambiguation.json` 为每个实体预先定义 `canonical` 规范名、`type` 类型、`aliases` 别名列表
2. 在原文中按别名逐一匹配
3. 匹配顺序按“别名长度倒序”进行，优先命中长别名
4. 如果某个短别名完全被更长匹配覆盖，则丢弃
5. 所有命中的提及都映射为同一个 `canonical_name`

例如：

- “艾伦·图灵”
- “Alan Mathison Turing”
- “阿兰·图灵”
- “涂林”
- “杜林”

最终都归并到同一个规范实体。

输出结构包括两部分：

- `canonical_entities`：规范实体级别统计
- `mentions_in_text_order`：按文本顺序排列的提及明细

这说明项目区分了“实体”与“提及”两个层次，这是知识图谱项目中很重要的设计。

### 3.3 通用消歧器一：词袋相似度 + CRF 全局一致性 + LBP

代码位置：`src/crf_disambiguator.py`

这是项目中最值得在答辩时重点讲的一段算法代码，因为它不仅做局部分类，还做全局推理。

方法组成：

1. 对 mention 周围窗口构造词袋表示
2. 用 TF-IDF 风格权重构造各标签原型向量
3. 计算 mention 与各标签原型之间的余弦相似度，得到 unary potential
4. 从训练样本中统计标签转移概率，形成 transition potential
5. 对“同名 mention”或“别名 mention”建立一致性边
6. 使用 Loopy Belief Propagation 做近似全局推断

关键函数：

- `_train_bow_prototypes()`
- `_train_transition_mle()`
- `_unary_log_potential()`
- `_build_alias_groups()`
- `_decode_lbp()`

这相当于把消歧问题看成“序列图模型上的联合标注问题”，不是单个 mention 单独分类，而是让整篇文档的实体类型互相约束。

### 3.4 通用消歧器二：BERT-BiLSTM-CRF mention 级序列消歧

代码位置：`src/bert_bilstm_crf_disambiguator.py`

实现思路：

1. 将文档中每个 mention 的局部上下文切片出来
2. 用 BERT 对每个 mention 上下文编码
3. 取 `[CLS]` 向量作为 mention 表示
4. 将同一文档中的 mention 序列送入 BiLSTM
5. 用 CRF 在 mention 序列层面联合解码实体粗类型

关键类：

- `MentionSequenceDataset`
- `MentionBertBiLSTMCRF`
- `BertBiLSTMCRFEntityDisambiguator`

与实体抽取中的 BERT-BiLSTM-CRF 不同，这里建模的单位不是“字序列”，而是“mention 序列”。

### 3.5 答辩时如何概括实体消歧

可以直接说：

“图灵专题最终采用基于别名表的规则消歧，因为专题实体集合固定、解释性强；同时系统设计了两种通用消歧器，一种是词袋相似度与 CRF 全局一致性结合的图模型方法，另一种是基于 BERT-BiLSTM-CRF 的 mention 序列标注方法，说明系统具备从规则法向学习法扩展的能力。”

## 4. 关系抽取方法

### 4.1 方法概述

关系抽取采用“LSTM-CRF 触发词识别 + 规则约束配对 + 正则规则补充”的混合方法。

这一步不是开放域关系分类，而是专题知识抽取，因此更强调：

- 关系类型可控
- 规则透明
- 结果可验证

代码位置：`src/lstm_crf_relation_extract_turing.py`

### 4.2 触发词序列标注

模型类：`LSTMCRFTriggerTagger`

结构如下：

1. 字符 embedding
2. BiLSTM 编码
3. 线性层输出 `B-TRIG / I-TRIG / O`
4. CRF 做触发词序列解码

关键函数：

- `build_vocab()`
- `weak_label_trigger()`
- `train_trigger_model()`
- `decode_trigger_spans()`

训练方式：

- 不需要人工逐字标注触发词
- 直接从 `data/relation_rules_turing.json` 中收集所有关系触发词
- 在句子中自动打上触发词弱标签
- 用这些弱标签训练 LSTM-CRF

这说明项目把“规则知识”反过来用作训练信号，是一种弱监督思想。

### 4.3 基于规则的关系配对

关系规则文件：`data/relation_rules_turing.json`

每条规则定义了：

- `relation`：关系名
- `triggers`：触发词
- `head` 约束：头实体允许的规范名或类型
- `tail` 约束：尾实体允许的规范名或类型
- `pairing`：配对方式
- `max_pairs`：最多配多少对
- `head_before_tail`：是否要求头实体在前
- `trigger_between`：是否要求触发词位于头尾之间
- `tail_side`：尾实体必须在触发词前/后/任意侧

关键函数：

- `load_rules()`
- `mention_match()`
- `type_match()`
- `pair_candidates()`

配对策略本质上是：

“先根据规则筛选候选 head / tail，再按照距离触发词最近、顺序约束最合理的原则打分排序，最后选出最优实体对。”

这一点非常适合答辩，因为它说明关系抽取不是盲目连边，而是带有语法位置约束和实体类型约束的。

### 4.4 主实体注入

关键函数：`inject_main_entity_mentions()`

这是图灵专题关系抽取的一个定制技巧。

很多句子里写的是“图灵”“Alan Turing”，甚至有时只写代称。为了保证“主角实体”不缺失，代码会：

1. 读取配置中的 `main_entity`
2. 检查句子中是否已存在该实体 mention
3. 若没有，则用 `main_aliases` 去句子中匹配
4. 手动补入主实体 mention

这样可以显著提高“图灵 -> 某属性/某关系”的抽取完整性。

### 4.5 正则规则补充

关键函数：`extract_regex_triples()`

为什么还需要正则规则？

因为有些关系非常适合用模板句直接抽取，例如：

- 又名
- 国籍
- 居住地
- 享年
- 荣誉称号
- 赦免人数
- 计时方式

这些关系如果只依赖触发词和实体配对，可能会漏；而正则模板能高精度补足。

因此，最终关系抽取是三部分叠加：

1. LSTM-CRF 找触发词
2. 规则约束做 head-tail 配对
3. 正则规则直接补充高精度三元组

### 4.6 关系抽取代码逻辑总结

`extract_relations()` 的整体逻辑是：

1. 句子切分
2. 训练触发词识别模型
3. 在每句中识别触发词
4. 对每条关系规则筛选符合约束的实体
5. 根据规则选择 head-tail 配对
6. 生成三元组
7. 用正则规则补充额外三元组
8. 去重并统计关系类型

因此关系抽取可以概括为：

“弱监督触发词识别 + 规则驱动关系判定 + 正则模板补充”

## 5. 三元组生成方法

### 5.1 三元组的来源

代码位置：`src/lstm_crf_relation_extract_turing.py`

真正的三元组生成在 `extract_relations()` 中完成。程序会为每条有效关系构造：

- `head`
- `relation`
- `tail`
- `head_mention`
- `tail_mention`
- `trigger`
- `rule`
- `evidence_sentence`

也就是说，输出不只是裸三元组，还保留了证据句、触发词和命中规则，方便答辩时说明“结果可追溯”。

### 5.2 去重与规范化

关键机制：

- `normalize_name()`：对实体名做显示层标准化
- `seen_triples`：按 `(head, relation, tail)` 去重

`normalize_name()` 会处理：

- 显示名映射
- 括号附加说明去除
- 某些地名、程序名、缩写的人工修正

这说明三元组生成前做了轻量知识清洗，避免同一实体因为表述不同产生重复节点。

### 5.3 为什么三元组适合作为中间层

本项目把“三元组”作为图数据库导入前的中间表示，非常合理：

1. 三元组是知识图谱最标准的抽象形式
2. 便于检查抽取质量
3. 便于后续导出为 Neo4j、RDF 或其它图格式
4. 便于答辩展示关系网络

## 6. Cypher 脚本生成方法

### 6.1 代码位置

`src/generate_neo4j_cypher.py`

### 6.2 生成逻辑

Cypher 生成分三步：

1. 读取三元组文件 `outputs/turing_kg_triples.json`
2. 读取消歧实体文件 `outputs/turing_entities_disambiguated.json`，建立实体到类型的映射
3. 根据实体类型推断 Neo4j 节点标签，输出节点和关系创建语句

关键函数：

- `load_triples()`
- `load_entity_type_map()`
- `infer_label()`
- `build_cypher()`

### 6.3 节点标签推断

代码中定义了：

- `TYPE_TO_LABEL`
- `LABEL_ORDER`
- `VAR_PREFIX`

例如：

- `Person -> :Person`
- `Organization -> :Organization`
- `Work -> :Work`
- `Concept -> :Concept`
- `Device -> :Device`
- `Date -> :Date`
- 数值类实体可能映射到 `:Numeric` 或 `:Year`

如果一个实体不在消歧类型表中，则：

- 检查是否是日期
- 检查是否是年份
- 检查是否含数字
- 否则回退为 `:Entity`

这一设计保证了 Neo4j 图中既有明确语义节点，也允许保留无法完全判定的通用实体。

### 6.4 Cypher 输出风格

程序生成的 Cypher 脚本大致分两段：

1. `CREATE` 节点
2. `MATCH` 已创建节点并 `CREATE` 关系

优点：

- 节点先创建，关系后建立，结构清晰
- 变量名按类型分组生成，如 `p1`、`o1`、`c1`
- 字符串经过 `cypher_quote()` 转义，避免引号和换行破坏语句

从答辩角度可以说：

“程序先把自然语言知识抽象为三元组，再把三元组映射为图数据库中的节点标签、属性和关系类型，实现了从文本到 Neo4j 图结构的自动转换。”

## 7. 通用主流程代码分析

### 7.1 `src/run_pipeline.py`

这是项目的通用总控脚本，职责是：

- 解析命令行参数
- 加载本地文本与网页文本
- 选择 NER 后端：`crf` / `bert_bilstm_crf` / `cogie`
- 选择消歧后端：`crf` / `bert_bilstm_crf`
- 调用细粒度类型器补全细标签
- 导出 `entities.json` 与 `entities.csv`

它体现了项目的“模块化可插拔”设计。

### 7.2 细粒度类型补充：`src/fine_grained_typing.py`

该模块不是深度学习模型，而是一个轻量规则型细粒度分类器。

方法：

- 对 mention 文本做关键词打分
- 对上下文做关键词打分
- 给粗粒度父类标签一个先验分
- 最终按加权分数选择细粒度标签

得分公式在 `predict()` 中体现：

- mention 线索权重 `0.60`
- context 线索权重 `0.30`
- coarse label 先验权重 `0.10`

这说明项目对“实体类型”做了两层表示：

- 父类：PER / ORG / LOC ...
- 子类：PER.Scientist / ORG.University / WORK.Book ...

### 7.3 文本源模块：`src/text_sources.py`

该模块负责：

- 读取 `datafile/` 下本地 txt
- 解析网页 URL
- 抓取 Wikipedia 或普通网页正文
- 生成统一的 `TextDocument`

这部分使系统不局限于单个 txt 文件，而具备从网页扩展知识源的能力。

### 7.4 CogIE 适配器：`src/cogie_adapter.py`

这个文件提供第三种 NER 后端的兼容层，用来对接 CogIE 工具包。它说明项目在架构上考虑过外部工具接入。

### 7.5 Wikipedia 抓取器：`src/wiki_crawler.py`

该模块实现：

- 维基页面抓取
- 正文抽取
- 分类、章节、链接提取
- 小规模 BFS 式爬取

它并不是图灵主流程的必经步骤，但说明项目具备向“多页面知识采集”扩展的基础。

### 7.6 模型下载脚本：`src/download_bert_model.py`

用于把 `bert-base-chinese` 下载到本地 `models/bert-base-chinese`，解决离线运行问题。

## 8. 图灵专题主流程代码分析

### 8.1 `src/train_and_extract_turing.py`

作用：

- 图灵专题实体抽取总入口
- 加载词典
- 自动构造弱监督样本
- 训练 BERT-BiLSTM-CRF
- 生成 `turing_entities.json`

它是“专题 NER 构建器”。

### 8.2 `src/disambiguate_turing_entities.py`

作用：

- 读取图灵文本

- 生成 `turing_entities_disambiguated.json`

它是“专题实体归一化器”。

### 8.3 `src/lstm_crf_relation_extract_turing.py`

作用：

- 读取关系规则
- 训练触发词 LSTM-CRF

它是“专题关系抽取与三元组生成器”，也是整个项目最核心的知识图谱构建逻辑。

### 8.4 `src/generate_neo4j_cypher.py`

作用：

它是“图数据库导出器”。

## 12. 可以直接用于答辩的总结

### 12.1 本项目的方法特色

可以概括为五句话：

1. 实体抽取采用“专题词典 + 弱监督 BERT-BiLSTM-CRF”的混合方案
2. 实体消歧采用“别名表归一化”为主，同时设计了 CRF 和 BERT 两种学习型消歧器
3. 关系抽取采用“LSTM-CRF 触发词识别 + 规则约束配对 + 正则模板补充”
4. 三元组输出保留了规则来源和证据句，结果可追溯、可解释
5. Cypher 生成模块将三元组自动映射为 Neo4j 图结构，实现文本到图数据库的完整闭环

### 12.2 本项目为什么适合图灵专题

因为图灵知识具有以下特点：

- 领域范围清晰
- 核心实体集合稳定
- 别名、多语种写法较多
- 时间、事件、作品、机构关系丰富

所以最合适的方案不是纯黑盒端到端，而是“规则与模型结合”的专题知识图谱构建方法。

### 12.3 如果老师问“你这个项目的创新点是什么”

可以回答：

1. 将专题词典、弱监督训练、深度序列标注和规则图谱构建整合在一个系统中
2. 实体抽取、消歧、关系抽取、三元组生成、Cypher 导出形成了完整闭环
3. 关系抽取不是简单关键词匹配，而是加入了触发词序列标注和实体类型约束
4. 实体消歧不仅有规则法，还设计了基于全局一致性的学习型方法
